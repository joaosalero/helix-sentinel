# Observability

The backend emits structured JSON logs and exposes `/metrics` for Prometheus scraping. Every HTTP response includes `X-Correlation-ID`, either supplied by the caller or generated by the API.

Local observability runs through Docker Compose:

- Prometheus: `http://localhost:9090`
- Grafana: `http://localhost:3001`
- OpenTelemetry collector: OTLP gRPC `localhost:4317`, OTLP HTTP `localhost:4318`

Grafana is provisioned with a Prometheus datasource and a Helix Sentinel operational overview dashboard. Prometheus scrapes:

- the host-run API at `host.docker.internal:8000`
- Prometheus itself
- the OpenTelemetry collector self-metrics endpoint
- Grafana metrics

## Startup Order

Use `make up` to start PostgreSQL, Redis, Prometheus, the OpenTelemetry collector, and Grafana. Then run migrations and start the API from the host shell. Prometheus expects the host-run API at `host.docker.internal:8000`, so the API target will remain down until Uvicorn is running.

Start the backend with Uvicorn before expecting the API target to be up:

```bash
uvicorn helix_sentinel.main:create_app --factory --app-dir backend --reload
```

Health endpoints are split by purpose: `/api/v1/health` is process liveness, and `/api/v1/ready` checks PostgreSQL and Redis readiness. Readiness responses include dependency status and latency in milliseconds, and Prometheus exposes the same checks through `helix_readiness_dependency_status` and `helix_readiness_dependency_duration_seconds`.

OpenTelemetry instrumentation is environment-gated through `HELIX_OTEL_ENABLED`. When enabled locally, the API exports OTLP traces to `HELIX_OTEL_EXPORTER_OTLP_ENDPOINT`, which defaults to `http://localhost:4317`.

Event ingestion adds Prometheus counters for accepted events by category and severity, and rejected events by validation reason. Ingestion audit events use the same correlation ID as the HTTP request.

SOC analytics adds counters for endpoint usage and histograms for aggregation latency. Analytics logs include correlation IDs and aggregate counts only; raw event payloads are not logged.

Detection Engineering adds counters for rule imports, parse failures, and API usage. Import and parse failure audit events include correlation IDs and sanitized metadata only.

Threat Analytics adds counters for endpoint usage and generated correlations by insight type, plus histograms for correlation latency. Logs include correlation IDs and insight counts, not raw payloads.

AI-assisted analytics adds counters for API usage and generated anomaly types, plus histograms for scoring latency. Logs include correlation IDs and finding counts only.

IOC enrichment adds counters for API usage, IOC creation, event-to-IOC matches, and enrichment execution latency. Logs and audit events include correlation IDs, aggregate counts, source names, and confidence values only; raw event payloads and secrets are not logged.
